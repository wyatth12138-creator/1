# VidEoMT / Cutie 对象状态适配

可以吸收。当前实现选择把对象状态纳入原任务效用记忆：保留什么历史、读出什么对象证据、下一帧怎样初始化查询，都受同一可淘汰记忆约束。模型继续使用SAM2.1 Small。

## 已有部分与实际缺口

原TUM-US的SAM2路径已经通过memory attention读空间记忆和object pointers，不能将“新增对象指针”当作贡献。实际缺口是_read每帧重新用target/task/anatomy embeddings生成固定语义query；对象指针没有直接返回该query。分类也主要读取全局图像token。

[VidEoMT](https://arxiv.org/abs/2602.17807)把前一帧查询与当前可学习查询融合，并在普通ViT内联合处理时空信息。[Cutie](https://arxiv.org/abs/2310.12982)从对象摘要生成query，与像素特征交互，区分前景/背景。本实现借鉴两者的表示原则，采用SAM2解码端适配，不是完整VidEoMT的encoder-only模型，也不是完整Cutie的迭代query transformer；原论文速度、跟踪成绩不转移为本模型结果。

已查官方代码固定版本：tue-mps/videomt@f351ccbfb2096c71bf3bce6241c8eb257c5cffeb，hkchengrex/Cutie@ec5cdd4cf16f75c73ad785a2f96fb97dbad4125a。VidEoMT官方仓库还列出PMT/LVMT等后续工作，因此持续查询或GRU记忆本身也不能单独称为新颖。

## 实际实现

1. query_propagation：从当前记忆中最近仍保留的对象pointer初始化下一帧query，与当前语义query做门控残差融合。门控仅使用已有query、pointer、模型预测quality和时间间隔。FIFO通常保留最新帧；效用策略可拒绝最新低价值帧，因此不是无条件沿用上一帧错误。
2. object_memory：从当前模型预测mask和特征池化每个目标的前景、背景摘要，写入MemorySlot.object_tokens。读出按目标/视图分别在保留的时间点上注意，不混合不同语义目标。前景减背景的对象证据参与空间特征增强。
3. 分类接入：相同预测对象摘要进入当前全局分类token，历史分类token也随同一记忆保留。分类样本不要求真实mask；分割和分类仍来自不同数据集，所有对象池化只用预测。真值只计算实际可用监督和离线效用标签。

所有状态都在该病例、该窗口的MemoryBank内；没有额外last_query缓存或累计对象EMA。删除一个槽会同步移除空间记忆、pointer和前景/背景摘要；rollout也会重算各分支的未来对象状态。这样现有效用标签衡量的是删除整份历史证据的后果。

三个残差系数从0开始，原读者在初始化时输出一致，随后可学习使用新分支。原生合成验证已检查初始等价、启用后作用、病例重置、前缀因果性、GT输入不变性、三目标/双视图、完整训练/效用/扩展与紧凑检查点重载。

## 使用

保留默认原生读者作为基线；新增config/object_state.json启用两个功能。先用已恢复映射的库存准备候选输入：

```powershell
python .\utils\prepare.py --inventory 'data/dataset_task_manifest/dataset_task_manifest.jsonl' --config .\config\object_state.json --index-cardiac --output 'run/object_inputs'
python .\train.py --config 'run/object_inputs/prepared_config.json' --stage run --output 'run/object_candidate'
```

run完整执行读者、效用采集、控制器、四个控制器对照、重采集、政策评价和来源扩展。旧读者检查点可以继续按旧模型配置使用；新增分支需要实际训练，不能靠加载SAM2官方权重就声称获得收益。

完整四臂多种子比较：

```powershell
python .\train.py --config 'run/object_inputs/prepared_config.json' --stage object-study --output 'run/object_study'
```

|读者臂|查询传播|对象摘要读写|
|---|---|---|
|native|关|关|
|query|开|关|
|object|关|开|
|combined|开|开|

每臂从相同官方SAM2与配置种子独立训练；object-study在模块初始化后再设相同训练随机种子，减少额外模块初始化对共同训练随机流的干扰。各自开发集选模，然后冻结读者比较FIFO、任务效用及其余政策。不同臂不共享已训练读者；同一臂的政策比较才使用完全相同的冻结读者。每臂仍包含原完整控制器对照和扩展作业，四臂三种子会显著增加总实验量。

输出object_study.json保存各子作业路径、逐来源配对差，以及四条件交叉作用：

    (combined/TUM − combined/FIFO) − (native/TUM − native/FIFO)

这能区分“读者本身更强”与“任务效用选择特别有助于对象状态”。统计同时对种子/实体配对，不把四个独立区间拼成显著性结论。没有真实数据结果时，这只是可检验假设。

## 代价与验证边界

组合桥接额外461,574个参数；不更换ViT骨干。float32对象摘要每目标/视图/槽额外2048字节；三目标单视图每槽6144字节。MemorySlot.nbytes已计算此项。比较同时报告真实字节和时延，同槽数不等同于同字节。

前景与背景注意力在batch维合为一次调用，共享权重，互不跨分组注意。固定合成微基准从约0.753ms降为0.485ms，最大输出差约2.38e-7；这是该读出部分的微基准，不是整个模型速度或精度结果。

现有CAMUS/EchoNet主要提供解剖结构分割，不含自然视频那类多实例跟踪ID。因此当前验证对象是解剖语义槽的持续表示，不报告无依据的ID-switch/MOTA。EchoNet只在实际标注帧评估正确性，预测平滑不能代替真实分割准确率。建议先看CAMUS多结构逐目标Dice和EchoNet两标注帧结果，再检查CEUS分类与静态任务是否有收益或退化。

如果组合只提高FIFO下的分割，效用交叉作用没有收益，应将结果解释为读者适配；如果任务效用能够在此状态表示下更好保留跨时距证据，才支持继续围绕“任务价值决定对象历史保留”的研究主张。两个已有机制的拼接本身不构成已证明原创。
