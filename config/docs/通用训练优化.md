# TUM-US 通用训练优化：工作1

本轮改善的是一个模型同时学习不同超声来源时的训练方式。图片、视频、B超和CEUS继续使用现有SAM2共享读者；分类与分割来自不同数据集，各自计算真实标注下的损失。没有“分类—分割时间对应”，也不要求同一病例具有两种标注。

## 已实现的机制

1. **共享部分处理冲突。** 每个更新分别积累分类、分割两类梯度，各占一半权重；每类内部轮换数据来源。`mean`直接平均，`pcgrad`在共同参与计算的参数张量上投影相反梯度。某类损失未使用的参数不会被另一类的投影凭空赋予梯度。逐实体求梯度后释放图，避免把整批视频计算图同时保留在显存。
2. **专属部分改变回传方向。** `consistent`先形成共享更新方向，再重算每类的一个真实训练实体，计算任务损失对共享FPN顶层卷积的梯度。利用真实混合二阶导数，仅修改对应专属参数，使该梯度更接近共同方向。额外修正范数最多为该类主梯度的10%，默认每4步一次。额外探针只取一个真实窗口、最多4帧，保留原始帧号及稀疏标注；它是短片段方向近似。主监督仍使用完整配置序列，头训练对照使用同样片段。探针使用保留下来的顶层FPN卷积，SAM2 Small为`neck.convs.1.conv.weight`；二阶导数使用FP32和math SDPA。
3. **选样独立于冲突。** 热身200步后，在每个来源自己的train候选池中，先按本任务预测不确定性保留候选，再用L2标准化表征的k-center选择覆盖较广的实体。分类用预测熵，分割用预测像素熵的90%分位数。默认每来源64候选、选一半，每400步刷新。不同来源不争抢名额，不用梯度冲突惩罚样本。

分类专属参数是全局分类读出器及对象桥的分类投影。SAM掩码解码器仍归共享部分：启用对象记忆后，分类也可能通过预测区域使用它。为给分割提供真正独立的输出参数，本轮可选增加每语义目标一个正比例和偏置，32目标共64个参数，初始为恒等变换。仅分割请求使用它。所有优化器对照均启用相同的64参数，避免把增加参数与优化器收益混淆。它与分类头的容量明显不对称；若增益仅来自输出校准，应据此解释。

这借鉴了ConsMTL“任务专属参数也决定共享梯度”的思想，但**不是原论文复现**。原论文在对齐的任务表征上组合梯度，本实现对独立数据源改用共同参数坐标、余弦目标和PCGrad方向，并只在小探针上约束。ODS的CTMI需要同一输入上可信的多任务预测，当前不具备该前提，因此没有移植CTMI。

选样只用于读者训练的已有标注重采样；控制器效用采集阶段仍可使用全部train实体。本项目不因此声称减少了整项研究的人工标注量。候选评分不读真值掩码或标签值，但使用当前任务的输入及预测。

## 实际数据与比较

当前默认共同训练：BUS-BRA、Appendix图片分类；BUSIS、Fetal_HC图片分割；CAMUS视频分割；私有Breast CEUS分类。EchoNet及其他CEUS器官继续按照配置作跨来源评估/接入。CAMUS和EchoNet继续沿用已核对的MemSAM原帧映射与各自采样方式，不改成同一种假设。六个来源不等于六种任务均已有有效训练证据；`video_cls`仍是预留接口。

`utils/mtl_study.py`生成8组×配置中种子的完整比较：

|优化方式|全部train实体|不确定性＋覆盖重采样|
|---|---|---|
|来源平衡的普通平均|mean_all|mean_cover|
|只处理共享梯度|pcgrad_all|pcgrad_cover|
|共享冲突处理＋专属方向修正|consistent_all|consistent_cover|
|共享冲突处理＋额外监督头训练|head_replay_all|head_replay_cover|

最后一行使用相同额外实体、间隔和修正范数上限，检验“方向调整”是否优于单纯多练一次任务头。它不是精确等二阶计算量对照，须同时报告墙钟时间/峰值显存，并补充等GPU时间曲线。各组初始化、模型结构、来源轮换、主监督更新数、开发选模和FIFO评估策略相同。更换控制器的收益另做实验，避免混入读者优化效果。

主要看逐来源AUROC、Brier、Dice及患者级区间、最差来源退化和训练成本。开发选模仍使用来源平均Brier或1−Dice；不能把AUROC与Dice的原始方差叫作公平性。若需要相对单任务公平性，先实际训练相应单任务对照。旧的`--stage baselines`用于关闭本多任务优化器的单任务配置。

## 运行

在项目根目录执行以下命令。数据清单、配置展开、日志、权重和比较结果全部放独立输出目录。下面命令由操作者执行真实训练。

```powershell
# 元数据准备不解码影像；CAMUS/EchoNet必须保留各自已验证帧映射。
python utils/prepare.py --config config/consistent_mtl.json --inventory run/cardiac_index/inventory_trainval.jsonl --frame-map run/cardiac_index/frame_map.json --output run/mtl_prepared
# 先生成全部比较配置，不启动训练。
python utils/mtl_study.py --config run/mtl_prepared/prepared_config.json --output run/mtl_comparison
# 单种子整条流程：读者、效用采集、控制器、对照、复制回训、任务接入。
python train.py --config run/mtl_prepared/prepared_config.json --stage run --seed 3407 --output run/mtl_full_seed3407
# 同一套配置执行8组×全部种子的读者比较，仅dev、固定FIFO。
python utils/mtl_study.py --config run/mtl_prepared/prepared_config.json --output run/mtl_comparison --execute
```

读者阶段记录`multitask_partition.json`、`multitask_updates.jsonl`、每次`selection_*.json`、逐来源开发结果、可恢复优化器/调度器/RNG/选样索引和最终读者。CUDA支持BF16时主梯度BF16前向、FP32积累；否则使用FP32，避免手工梯度混合中的未缩放FP16。

## 论文能主张什么

当前交付是可运行训练机制，不是“已证明通用性更强”。把ConsMTL、PCGrad和覆盖选样组合起来本身不足以形成原创方法贡献。值得检验的问题是：**在任务标签不配对、输入从图片扩展至视频和双视图CEUS时，只调整输出专属参数，能否减少共享读者的负迁移，并保留来源覆盖？** 若八组比较、额外头训练对照和等计算预算均支持，才有较完整的方法证据。若仅某个来源获益，则应报告适用条件，而不宣称普遍改善。

官方来源：[ConsMTL CVPR2025](https://openaccess.thecvf.com/content/CVPR2025/html/Qin_Towards_Consistent_Multi-Task_Learning_Unlocking_the_Potential_of_Task-Specific_Parameters_CVPR_2025_paper.html)、[MTLlib](https://github.com/jianke0604/MTLlib)、[ODS](https://arxiv.org/abs/2610.23623)、[ODS代码](https://github.com/Juho-Jung/multitask_active_learning_official)。本轮没有把上述仓库代码复制进运行项目。
